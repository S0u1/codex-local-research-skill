# 采用判断离线前向验证

日期：2026-10-11。覆盖 workbench-research 与 local-research 的采用判断/反馈分支。测试输入是 `adoption_cases.json` 中的四个虚构案例，不是用户真实项目效果记录。

方法：由未编写该模块的另一位 Agent 阅读两套采用判断规范及各案 request/materials 后独立回答；checks 未随输入提供，答复完成后再逐项核对。本轮不运行案例中的工具、不访问账号、不写业务档案，也不评估真实产品转化率。

| 案例 | 实际答复要点 | 核对结果 |
| --- | --- | --- |
| keep-current | 保留现有 CPU 采访流程；中文人名返工才是瓶颈，GPU 英文短句速度演示不证明人名改善；不给工时估计或直接替换建议 | 4/4 约定满足 |
| test-before-adoption | 仅提供同一库存 CSV 与当前工具/B 的对照计划；核前导零、金额小数和记录；支持 CSV 不等于语义保真；通过只限同类输入，失败继续原工具；不执行 | 4/4 约定满足 |
| conditional-feedback | 不直接采用 v0.5；v0.4 的快仅是用户定性反馈，漏人名未满足 R 的双条件；内存优化不证明修复人名；不编计时/成功率，不永久否定全部版本 | 5/5 约定满足 |
| bounded-adoption-counterfactual | 支持当前环境下已验证的两份同类 UTF-8 库存 CSV 任务采用 D，12→4 分钟明确来自用户提供的记录；不扩到全部格式。换成 XLSX 公式/宏项目时保留原工具，因为瓶颈与硬要求变化且无相关证据 | 5/5 约定满足 |

审阅结果：四案均能把建议回指给定证据与项目条件，未出现虚构数字、无视硬约束、把用户反馈当独立实测，或未经请求执行/归档。正向采用及条件变化案例用于检验流程不会一律拒绝新方案；三个跨域案例与模块的视频示例不同。

边界：这是指令层的离线行为回归与人工证据核对，不是随机对照评测，不证明真实工具更快、研究效果提升某个百分比，也不替代用户实际试用。后续修改分支时可重新运行这些输入，不把本次答复当永远有效的结论。
