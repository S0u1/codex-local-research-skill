# 本地归档契约

## 文件夹与归类

根目录按 SKILL.md 选择。首次实际归档才创建所需目录，不预建空分类树。优先沿用已有分类名称，用户指定分类优先。未指定时按研究主问题选一个主主题（例如 AI、自媒体、商业、游戏制作）；难以判断才用“待分类”，不要全部放入待分类。

```text
<root>/
  INDEX.md
  <主题>/
    INDEX.md
    github/<YYYY-MM-DD>-<owner>--<repo>/
      report.md
      sources.md
      assets/                  # 按需保存实际证据
    douyin/<YYYY-MM-DD>-<video-id>/
      report.md
      sources.md
      transcript.txt           # 有转写才创建
      transcript.srt
      assets/
    x/<YYYY-MM-DD>-<post-id>/
      report.md
      sources.md
      assets/
    digests/<YYYY-MM-DD>-<主题短名>/
      report.md
      sources.md
  .state/                      # 仅增量任务需要
  .staging/                    # 仅采集工具需要
```

单仓库用规范 owner/repo，抖音和 X 用经过核实的数字 ID 去重。跨主题条目只保留一个主档案，以报告 tags 和其他主题 INDEX.md 的相对链接关联。多项目比较放在 digests，保留全部仓库身份与来源。

路径组件移除 `/`、`\`、控制字符和 `..` 等路径跳转成分；保留中文主题，过长标题截短并保留来源 ID。创建前确认解析后路径仍在选定根目录内；解析软链接后也检查写入范围，不通过链接写出归档根目录。兼容 Windows 文件名：替换 `<>:"|?*`，去除尾随点和空格，避开 CON、PRN、AUX、NUL、COM1–COM9、LPT1–LPT9 等保留名称，去重时考虑文件系统大小写规则。

先检索根索引及匹配来源 ID。已有完整报告且无需更新时复用并链接；有新信息时新建日期版本并链接前版；同日重名增加 `-HHmmss`，仍冲突加序号。中断任务继续其现有未完成目录。不得覆盖历史报告或用户笔记。

## 文档内容

`report.md` 默认用简体中文，用户指定其他语言时跟随用户，文件头至少记录：标题、来源类型、规范 ID/URL、主主题、tags、实际调研时间（含时区）、证据范围、状态。状态使用 `collected`、`partial`、`complete`、`failed`，分别指仅采集、有分析但关键证据缺失、本次请求范围已完成、执行失败。`complete` 不表示获取了整个平台全部内容。

正文先写结论与适用场景，再按来源流程写关键发现、证据、限制和有依据的下一步。章节随材料调整，不凑篇幅。仅采集任务可以没有 report.md，索引链接 sources.md 并标 collected。

`sources.md` 记录来源 URL、作者/仓库、查询时间、原始标题、实际获取范围（全文/节选/转写/仅元数据）、证据文件相对路径和采集失败信息。只保存任务所需且允许保留的来源材料或短摘录，不为归档强行复制整篇受版权保护文章。不得保存 cookie、令牌或其他认证秘密。

## 索引与验证

根 INDEX.md 按主题链接主题索引；主题 INDEX.md 记录日期、标题、来源、来源 ID、状态、一句话结论与文档相对链接。更新前读取现有内容，保留用户文字与旧版本条目，不整文件盲目覆盖。重复任务不重复插入同一产物。

验证本次文件存在、内容可读、来源 ID 与 URL 一致、索引和内部文件链接能解析。状态只有在需要的证据与分析已完成后才能变为 complete。部分失败仍保存已获得资料和缺口，不能用完整完成掩盖。

交付报告与主题索引的绝对路径链接。归档是本地文件写入，不需要外部凭据、数据库或 Web 服务。
