# 抖音收藏读取与分析

## 先读取收藏列表

按 onboarding.md 检查连接和账号，在实际收藏入口确认“收藏 → 视频/图文”。可从 `https://www.douyin.com/user/self?from_tab_name=main&showTab=favorite_collection` 进入，入口变化时依实际页面导航。不能把“喜欢”、推荐流或搜索结果当收藏。浏览器工具及扩展必须来自当前宿主的实际接入方案，不假定某个私有脚本已安装。

普通整理默认最近 20 条，按可见顺序读取并去重；真实末尾不足 20 条则报告实际数量。用户要求全部时分页/滚动并记录覆盖范围，遇到验证、失效或连续三次无新条目时停止并保留进度。增量按 incremental.md 到旧边界，不以固定首屏代替完整增量。

逐条保存核实的数字 ID、真实 URL、标题、作者、说明、内容类型、可见时长与读取时间。以实际收藏条目为依据，引用视频不替代主条目。短链需要解析后核对身份，不从标题猜链接。保存本批清单后获取正文或媒体证据；元数据已采集不等于分析完成。

默认分析范围内每条收藏，主题从内容归纳。不能用相关度打分、营销判断或“信息量低”先丢弃收藏；低价值内容可给简短结论。只有用户明确设置过滤条件才记录 filtered 及原因，并与失败区分。搜索新选题、刷推荐流不属于这个流程。

## 推荐下载与转写

使用 [安装说明](collectors.md) 配置本包的 `scripts/sync_favorites.py`。先由浏览器保存已核实的 `items` 清单，再将 `--items-file` 指向该文件，`--output` 指向归档根目录下该账号专用 staging 目录。只下载使用 `--transcriber none`；完整口播分析需要 `--transcriber local` 并验证 FFmpeg/WhisperX，或已有可用字幕。

脚本不读取收藏列表、不自动生成分析、也不负责统一增量基线。其 `.download-state.json` 不能代替本技能的收藏状态。输出 JSON 的 downloaded/transcribed/reused/failed/pending 与 blocked 要逐项处理，不能只看退出码或下载数量。阻塞时暂停该来源，已下载但尚未转写可用同一清单补转写。

## 获取收藏内容

图文读取实际文字和可见图片，不送进视频下载/转写工具。视频读取可用字幕或通过已配置的媒体获取与转写工具获得内容。先核对来源身份，不能只读标题就形成完整分析。

已有本条转写可复用；优先读取平台可用字幕，缺少时通过已配置且允许使用的下载/转写工具获取。用户提供的媒体或转写仅作为其选择的备用输入。不要假定本机装有任何旧技能脚本或转写模型。

需要外部工具时先检查其实际帮助和文档，确认能指定输出目录。临时材料写到 `<root>/.staging/douyin/<batch-id>/`，最终证据放到条目目录。不能限制输出范围的工具不直接运行，改用已有材料或说明缺少的能力。模型、语言、设备与参数以当前工具能力和用户要求为准；只有用户明确同意将媒体发送到云端时才使用云转写。

没有下载或转写能力时，保存实际可见元数据与来源，标 collected；已有部分正文或字幕可进行有限分析并标 partial。交付时明确缺少哪项输入，不能用视频标题推断完整内容，也不因此阻塞其他可完成条目。

核对媒体、字幕与请求的来源 ID 一致，再保留所需 metadata、transcript.txt、transcript.srt 及媒体证据，sources.md 记录来源和中间位置。采集完成不代表分析完成。恢复时复用已有中间产物和转写，不因工具 seen 状态跳过分析，也不自动清理恢复材料。

## 分析

读取真实转写与元数据，按需读 SRT 或观看关键画面。无转写不能编造口播；ASR 修正注明不是逐字原话，视觉观察记录时间和实际可见内容。

报告按内容类型（访谈、教程、案例、观点、测评）组织：简要摘要、核心主张、钩子与结构、证据与例子、可行动想法、不确定性。长材料补主题或步骤详解，保留具体工具、参数、数字、人物和案例；有时间戳时附引用。

只有材料支持新机会时写产品方向：用户、场景、最小形态、时机证据与最低成本验证。延伸分析区分作者观点与自己的判断，锚定具体材料。短推广保持短，不强凑章节和篇幅。

画面理解使用本次可用且授权的能力，不自动投递外部视觉服务。所需视觉缺失时记录 partial；不等待不存在的后台任务。报告实际收藏数、重复、用户明确过滤、采集/转写/分析和失败的数量，以及本地文件链接。
