# 本地增量与恢复

状态仅服务本技能，使用 `<root>/.state/<source>-<account-key>.json`；账号 key 必须经过路径清理。按来源与已核实账号分开，记录 checked_at、seen_ids、任务的 canonical_id/url/status/artifact_path/error、扫描范围及是否到达旧边界。小批任务可直接维护 JSON，无需运行常驻 worker。

首次或配置定时前先读 [初始化与定时准备](onboarding.md)，核实运行环境和用户选择的模式。收藏主题过滤仅在用户要求时启用，分类主题不自动变成采集过滤；定时主题搜索与推荐流需保留用户的主题/探索选择。搜索结果和推荐流不是按收藏时间排列的增量，重复执行时按来源 ID 去重并记查询覆盖范围，不套用收藏旧边界规则。

仅未来新增的任务还需记录 baseline_observed_at、monitoring_started_at、activation_status 与边界依据。准备阶段取得的基线标为 provisional，不代表已经启用；环境就绪后，在正式启用时重新采集基线并将当时已见内容排除，之后才分析新增。若只能在第一轮定时执行时建立基线，则以该轮成功观测为监测起点并告知用户，不能沿用数天前的准备基线冒称从启用时开始。平台缺少可靠收藏时间时，只能保证相对已观测基线的新增，不能保证精确 saved-at 时间边界；扫描范围不完整或置顶重排时沿用下面的 incomplete 规则。

首次只建立观测基线，除非用户要求处理现有收藏/Star/指定批次；明确基线不等于完成分析。首次收藏基线仅覆盖实际可见项，后续只有可靠到达该边界时才能宣称相对该基线完成增量。

GitHub 使用可用的只读 API 或 gh 获取个人 Star 列表并核实账号，读取全部分页才推进完整基线，不把 Trending 当 Star。抖音和 X 使用已登录可见收藏页，按最新顺序扫描至已知边界或真实末尾；默认每来源最多 200 条或 10 分钟。重排、置顶、分页失败或未到边界时保留旧基线并记录 incomplete，不说没有新增；采集时间不等于收藏时间。

观测 seen_ids 和分析完成状态分开。已见但 partial/failed 的任务仍可恢复，不能因 ID 已见而跳过未完成分析。以 source + canonical_id 去重，先完成已有未完成项；大批任务每来源每轮默认分析最多 3 条，完整批次请求继续后续批次至完成或明确阻塞，不能当作只登记任务。

更新状态前读取最新文件，使用同目录临时文件与原子替换；若发现另一个运行者正在处理同一状态文件，避免并发写入并说明。只有文档与索引验证通过才记录 complete。失败记录原因，原因未解决不盲目重试；中断后依据真实文件恢复，最多三次失败后暂停该项。

不根据技能示例推定定时授权。用户明确授权定时运行时才通过当前可用的自动化工具配置；环境没有调度能力时说明仅支持手动运行，不承诺后台执行。配置时，保存本技能名称、绝对归档根目录、来源、账号和范围。无变化或无行动价值时保持安静，仅有新分析、新故障或需用户操作时通知。

在线定时任务遇到验证码、账号警告或明确限流时，按 onboarding.md 暂停受影响来源，记录 blocked_reason 与适用的 retry_after/恢复条件。账号类阻塞未解决前跳过后续自动采集；限流等待期内不继续请求。其他健康来源可继续，无状态变化不重复通知。
