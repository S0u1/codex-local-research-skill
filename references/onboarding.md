# 初始化与准备

## 首次介绍与选择

裸调用、只说“初始化”或询问功能时，先使用这样的简短介绍：

> 我可以读取你的 **X 书签、抖音收藏和 GitHub Star**，分析收藏内容，按主题整理成本地 Markdown 文档和索引，也可以定时处理新增收藏。
>
> 你想先连接哪个来源？可以选一个或多个。主题会从收藏内容自动归类，不需要提前填写。

用户已指定来源时直接复用。选择后确认或沿用账号和处理范围：最近若干条、全部已有收藏、仅未来新增。普通“整理收藏”未给数量时默认每个已选来源最近 20 条并告知；不强制等待数量确认。只初始化时验证列表元数据，不据此扩展为批量分析。

顺序是：介绍与来源选择 → 范围及本地目录 → 风险提醒 → 只检查选中来源的连接 → 实际读取列表验证 → 获取内容与分析归档 → 按需开启定时。没有主题也能继续，不用“你关注什么领域”阻塞读收藏。过滤主题只接受用户明确要求，归档主题不是过滤条件。

仅询问功能不创建目录或访问账号；已明确任务跳过菜单。每次仅提出阻塞当前步骤的关键问题，不让新用户填写全部平台的环境问卷。准备清单区分已验证可用、待用户完成、当前不需要。缺失时给具体操作、官方入口与成功判据，不以“请配置工具”结束。

首次配置时主动介绍各来源推荐方案，不等用户自己找工具：GitHub 用 gh；X 按 [采集安装说明](collectors.md) 选择固定版本 CDP 采集器；抖音使用随包下载脚本，并按需安装本地转写依赖。既有方式已验证可用则复用，不额外安装。X CDP 的平台规则风险、系统限制和独立浏览器登录须一并说明。

## 收藏连接的验收

每个来源分别记录：平台、实际账号、连接方式、读取范围、返回条目数、核实的 ID/链接、分页/末尾状态和 checked_at。用读取收藏列表作为 readiness 判据，不以一般浏览器/API 能用代替。首次连接只读少量真实元数据即可；空收藏必须验证是正确账号、正确收藏入口且列表已加载。

连接缺失时检查宿主已有工具，按下面对应步骤帮助接入。用户已授权安装则执行适配当前系统的安装和验证；未授权安装先给具体准备步骤。导出、粘贴正文只在用户选择备用方式时使用，并标为“手动导入”，不能标“在线收藏同步成功”。无可行在线读取方式时明确受阻来源，继续其他已就绪来源。

## 自动化访问提醒

首次在线接入平台前，向用户简短展示以下提醒；首次启用定时任务或显著增加采集规模时再针对本次配置提醒。不在每个条目重复，也不向仅分析本地文件的用户显示。提醒不是额外的免责签署或重复授权步骤，用户已明确的任务授权仍然有效。

> 自动化访问抖音、X、GitHub 等平台可能触发验证码、请求限流或账号限制；违反平台规则时还可能导致账号暂停或封禁。请谨慎使用并遵守相应平台的现行规则。低频、只读或已登录均不保证不会触发限制，也不代表平台允许该访问方式。

同时说明本次来源、访问方式和批量范围。平台之间规则不同：X 明确限制非 API 自动化（包括脚本操作网站），抖音协议包含自动化接入、收集和处理内容的限制，GitHub API 有主限流及次级限流；不能笼统说“控制速度即可安全使用”。当前规则与出处见 README 的平台风险提醒。技术连接成功不等于平台许可；优先使用平台允许且当前账号有权限的接口或用户提供的材料。

遇到验证码、异常登录、限流或账号警告时暂停该来源，保存已有进度并解释原因；不持续刷新、切换账号或代理绕过限制。明确的 API 限流按响应中的等待时间处理，重试次数有限；无法判断原因的 403 不自动当作限流。定时运行应记录暂停/冷却状态，后续轮次在问题解决或等待期结束前跳过该来源，首次出现或状态变化时通知；不能每轮重试相同账号阻塞。

## 1. 本地目录

按 SKILL.md 的优先级解析归档目录，并告知用户实际绝对路径。已有目录先读相关配置和索引。授权本地初始化或归档后，用随机命名且不覆盖已有文件的临时文件验证写入和读取；只清理本次探针。失败时显示具体原因并询问可写目录，不能静默写进技能安装目录。

默认主题可按内容归类，不要求用户预建文件夹。准备偏好可保存在 `<root>/.state/profile.json`；仅初始化/归档授权时写入，保留已有字段。记录 schema_version、archive_root、语言、启用来源、各来源任务模式、用户指定的主题/用途/排除项、核实的账号标识，以及每项能力的 status、checked_at 与验证依据。状态用 ready / needs_user / unavailable / unchecked。不保存密码、token、cookie 或完整环境变量。

环境能力记录只是上次观测，下次使用时重新验证相关登录、连接和目录，不当作永久就绪。当前指令覆盖保存偏好；一次性主题不自动覆盖用户长期兴趣，只有用户明确说以后沿用时才更新持久主题。

## 2. GitHub 准备

GitHub 收藏在本技能中指用户点过 Star 的仓库，不是自己的仓库列表、Watch 或 Trending。默认使用 gh 认证读取当前账号的 Star；已有支持该能力的只读连接器也可复用。Git 是版本管理工具，所需登录是 GitHub 身份认证，不是配置 Git 提交身份。验证账号后按 github.md 实际读取 Star 列表，能读某个公开仓库不代表已读到用户收藏。

选择 gh 路径时按顺序检查：

```bash
gh --version
gh auth status --hostname github.com
gh api user --jq .login
```

企业 GitHub 使用实际主机并按当前 gh 帮助调整，不默认 github.com。不执行 token 输出选项。gh 缺失时，根据实际操作系统和已有包管理器，从 [GitHub CLI 官方安装入口](https://cli.github.com/) 获取对应安装方法，向用户展示适用的具体命令或安装包入口；不要把不匹配系统的命令交给用户。

gh 未认证时，指导用户在自己的终端执行下面命令并在浏览器完成授权：

```bash
gh auth login --hostname github.com --web
```

不要让用户把验证码、密码或 token 发到对话。用户完成后重新运行认证状态与账号读取，并尝试读取本次目标。成功判据是“可读目标且账号正确”，不是命令存在。不因研究要求配置提交身份或推送权限。命令行为参考 [auth login](https://cli.github.com/manual/gh_auth_login) 与 [auth status](https://cli.github.com/manual/gh_auth_status)，执行时核对安装版本帮助。

## 3. 浏览器连接与平台登录

先检查当前 Agent 暴露的浏览器工具及其文档，辨认“只能抓公开网页”和“能操作用户已登录浏览器”的区别。公开网页读取不等于可以读取私人收藏。

- 已有可用连接：按工具规范读取标签页和目标页面，无需让用户重复安装扩展。
- 当前接入方案需要 Chrome 扩展：从该宿主或插件的当前官方文档取得准确名称、发布者、官方安装链接及配对步骤。向用户说明“安装该扩展 → 在所需浏览器配置文件启用 → 按宿主说明连接 → 打开目标页面”，步骤和按钮以实际文档为准。不猜扩展 ID、商店链接、CDP 端口或按钮名称。
- 工具列表不足以确定方案：只询问所用 Agent/版本及浏览器，再核实官方接入说明。无法核实安装入口时明确说明，不让用户安装任意同名扩展。
- 宿主没有浏览器接入能力：提供导出文件、正文、字幕作为当前可用路径；用户要在线采集时说明需要具备什么能力，不说装任意 Chrome 扩展就能解决。

连接成功后让用户在浏览器自行登录抖音或 X，打开收藏/书签页。Agent 实际读取页面标题、账号标识以及至少一个真实条目的 ID/链接；空列表必须可确认是已加载的正确收藏视图。平台网页登录和 Agent 浏览器连接分别验证，不能互相替代。认证失效或验证码需要用户处理，只暂停该来源。

X 推荐 CDP 采集器的安装命令、专用 Chrome profile 和只执行 collect 的约束见 [采集安装说明](collectors.md)。它不要求 Chrome 扩展；浏览器扩展仅是宿主提供的另一种连接方式，不把二者混作同一个必装组件。

## 4. 抖音收藏内容与转写

进入已登录账号的收藏页，按 [抖音收藏](douyin.md) 核对“收藏”而不是“喜欢/推荐”。主题从内容归纳，不要求用户指定；用户主动给过滤条件时记录该条件及未纳入条目。

口播分析先复用已核对属于本条收藏的本地归档转写，其次读取平台可用字幕；缺少内容时优先按 collectors.md 配置并使用随包下载脚本和 FFmpeg/WhisperX。用户手动提供的转写仅在其选择备用方式时导入，不能替代收藏列表读取验证。缺失时明确列出缺少的是媒体获取、音频提取还是转写，并依据系统、硬件与用户本地/云端选择查询工具官方安装说明，提供具体命令、模型首次下载需求和输出位置；不得仅以“先配置转写工具”结束。用户未授权安装时先给可执行准备步骤，不后台下载模型。云端处理必须明确获得上传媒体的同意。

用一个本次范围内的短片段验证可生成非空转写、来源身份匹配、输出目录正确。只测试片段不得声称整段视频已分析；完整分析仍按实际范围完成。没有任何可用媒体输入时说明阻塞，不为了验证擅自扩大采集范围。

## 5. 首条验证与完成

用户要求整理收藏时，从已读取且属于本次范围的条目中取一条，验证正文/字幕/仓库资料 → 分析 → 本地报告 → 索引，然后继续完成所选批次。无需用户再手动找链接。验证与批次共享记录，不重复分析或插入索引。

仅初始化时可验证少量收藏元数据和目录，报告“列表读取已验证，内容分析待验证”，不自动分析收藏。用户明确要求带跑通一条则分析一条真实收藏。仅未来新增按 incremental.md 建基线，不为首条验证分析旧收藏；准备期基线标 provisional。

初始化输出实际目录、所选来源与账号、处理范围、已验证能力及剩余准备步骤。只有用户选择手动备用方式时才使用其文件做首条验证，并说明没有验证在线收藏读取。不要把单来源可用说成三个平台全部就绪。

## 6. 定时准备

首次启用定时任务或显著提高频率、批量前，按上面的“自动化访问提醒”说明实际计划；已有风险提醒不需要逐轮重复。

用户要求定时运行时才检查调度工具，复用或更新相同任务，避免重复创建。确定来源、账号、处理范围、可选主题过滤、周期、时区和绝对归档目录；用户已明确的内容不重复确认。具体时间缺少且不能推断时先问，不能自行启用默认周期。

检查实际运行环境能否读取技能与持久目录、访问所需网络/登录会话，以及任务重叠如何避免。同机交互会话可用不代表云端或后台运行也可用。所需能力未就绪时先完成独立准备工作，保存具体调度方案并说明阻塞；不把无法执行的任务标为已启用。

首轮能手动验证时在用户授权范围内验证；仅建未来基线时允许分析链路待验证，但须明确。仅调度工具返回成功并核对其时间/时区/启用状态后，才能说定时任务已创建。记录工具返回的任务 ID 以便修改和停用；没有调度器则保留手动工作流，不承诺稍后自动执行。
